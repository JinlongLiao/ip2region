# 地区代码映射维护说明

本目录保存 IPv4/IPv6 维护代码共用的地区代码规则。功能操作入口见 [IPv4与IPv6解析及数据合并操作指南](../../maker/java/IPv4与IPv6解析及数据合并操作指南.md)。

## 1. 文件职责

| 文件 | 职责 |
| --- | --- |
| `国家名称代码映射.json` | 中文名称、显式别名、已确认名称修正及规则来源 |
| `UNICODE-LICENSE.txt` | Unicode CLDR 派生数据所需的许可证及归属声明，应与映射一起保留 |
| 本说明 | 配置维护方式与对解析、合并的影响 |

JSON 文件名保留历史名称，实际末列语义为“地区代码”。例如中国 `CN`、日本 `JP`、美国 `US`、澳大利亚 `AU`、泰国 `TH`；按用户选择，香港、澳门、台湾保留原标签和 `HK/MO/TW`，科索沃沿用 wlzn 的 `XK`。大洲、跨国区域及无法唯一确定的标签使用 `0`。

上述港澳台约定与 wlzn 原始数据的“中国/CN”不同，不能再将整个映射表描述为与 wlzn 完全相同。表中还可有 wlzn 当前数据未使用的合法代码，不代表数据中必须有对应区间。

## 2. 哪些 JSON 字段实际生效

| JSON 键 | 运行效果 |
| --- | --- |
| `名称代码` | Java/Python 实际查找表；中文别名也必须出现在这里 |
| `已确认国家字段修正` | 名称误填的显式修正，例如雅加达→印度尼西亚 |
| `旧数据别名` | 审计说明；不会在运行时自动合入查找表，新增别名还需同步 `名称代码` |
| 来源、官方来源、来源文件 SHA256 等 | 溯源信息；不能替代实际映射规则 |
| 非正式或特殊代码说明 | 审计元信息；不会自动改变查找表 |

配置键沿用现有接口名称，不因术语调整自动改名。不要只修改说明字段却期待结果改变。

## 3. Java 与 Python 如何读取

Java 的 `Ipv4CountryNormalizer` 虽保留历史 IPv4 类名，也被 IPv6 补丁代码复用。Maven 从 `../../scripts/data` 收集 JSON 与许可证，复制到产物资源路径 `ipv4-country-codes/`。类初始化时读入只读映射，后续查询复用该映射。

Python 的 `scripts/ipv4_country_codes.py` 在导入时从本目录读取相同 JSON；其他 Python 维护脚本调用这个模块。

修改规则后：

```bash
# 从仓库根目录校验 JSON 语法
python3 -m json.tool scripts/data/国家名称代码映射.json > /tmp/ip2region-region-codes.json

# 地区代码规则测试
python3 -m unittest discover -s scripts -p 'test_*.py'

# 重新正常构建，确保 Java 使用更新后的资源
mvn -f maker/java/pom.xml clean package
```

已有 Java 进程不热加载磁盘 JSON；更新源码规则后需使用新构建产物。Python 常驻进程也需要重新启动。原始 JSON、许可证、Java 及 Python 调用代码需一起交付；本项目已为该 JSON 添加仓库忽略例外，避免个人全局 `*.json` 忽略规则遗漏它。

## 4. 对 IPv4、IPv6 的不同影响

| 操作 | 规则 |
| --- | --- |
| Java IPv4 记录读取、清理、合并 | 根据名称修正字段并解析地区代码；未收录名称可能输出 0 |
| Python IPv4 完整文本补码 | 同样按名称修正和补码；要求完整连续 IPv4 空间 |
| Python 旧 IPv4 初次迁移 | 名称映射优先；未知名称再尝试严格上游区间匹配 |
| IPv6 源记录读取 | 保留原名称和地区代码，尤其保留 Japan/JP 等英文记录 |
| IPv6 补丁 | 明确中文名称可由 0 补齐；非零代码与明确名称冲突则拒绝；英文补丁使用显式代码 |

IPv6 补丁的“大洲与确认歧义标签为 0”还由 `Ipv6RegionSegment` 中的 `ZERO_CODE_LABELS` 执行。若新增区域标签，应同时核对该集合、JSON 说明与测试，不能仅修改 JSON 审计字段。

本目录配置只决定明确标签对应什么地区代码，不判断某个 IP 的真实归属。IP 边界与地域来自已确认的源数据和补丁；不同数据源意见冲突时不能靠代码表自动裁决。

## 5. 修改规则的步骤

1. 先确认是“已知名称补代码”“旧名称别名”“国家或地区字段误填”，还是“该 IP 归属改变”。前三项可涉及本目录，最后一项应制作 IP 区间补丁。
2. 查明来源，在 JSON 元信息保留可追溯依据。明确名称写入 `名称代码`；别名还同步审计字段；只有确实误填才修改名称修正规则。
3. 对歧义名称和大洲保留 `0`。不按上游当前地址归属强改自维护国家或地区，不把含糊名称任意对应到一个地区。
4. 为受影响情况补充 Java/Python 规则用例，再运行测试与正常构建。
5. 输出独立的候选文本、候选库，对补丁边界和范围外记录做查询对照。修改映射不会自动重写现有文本或 xdb。

例如给明确中文别名补码，应在 `名称代码` 中加入对应键值，并同步 `旧数据别名` 的说明。正式代码或特殊约定必须经确认；不要把随意的示例键直接加入真实配置。

## 6. 数据批量处理入口

```bash
# 当前完整 IPv4 文本补码
python3 scripts/补齐IPv4国家代码.py data/ipv4_source.txt /tmp/ipv4-codes.txt

# 旧布局 IPv4 初次迁移：第二个输入必须是真正的上游参考
python3 scripts/迁移IPv4数据.py data/ip.merge.txt /tmp/upstream-ipv4-source.txt /tmp/ipv4-migrated.txt
```

以上从仓库根目录运行，只写独立输出，要求输入完整连续覆盖 IPv4 地址空间。脚本不支持 IPv6，也不是持续修订任意局部数据的通用工具。

IPv6 的同格式区间补丁直接交给 Java `Ipv6MergeApp`；具体命令、示例和制库步骤见 [操作指南](../../maker/java/IPv4与IPv6解析及数据合并操作指南.md)。

## 7. 许可证与来源

JSON 记录了 Unicode CLDR release-48 中文名称来源、来源文件 SHA256、项目别名及特殊约定。本目录保留 [Unicode 许可证](UNICODE-LICENSE.txt)。后续更新时同时核对来源、许可证及本项目差异，不把 CLDR、ISO 标准代码与本项目特殊约定混为一谈。

## 大洲归零与输出保护

`强制零地区代码标签` 是 Java IPv4、IPv6 补丁及 Python 迁移/补码共用的显式规则。七大洲、中英文跨国区域和已确认的歧义标签必须使用 `0`，即使补丁或上游提供 `CN` 等非零代码也不继承。英文按大小写不敏感比较；未知名称不擅自归类。港澳台继续保留原字段和 `HK/MO/TW`。

两个 Python 入口均检查输出与全部输入的真实路径及硬链接身份。输出先在目标目录完整写入临时文件、同步落盘，再原子替换；写入、同步或替换失败保留已有输出并清理临时文件。要求输入输出目录由本次维护独占，不支持其他进程同时替换路径。输出为新文件，文件权限受临时文件默认权限控制，不继承旧输出的额外权限。

可使用 `python3 -m unittest discover -s scripts -p 'test_*.py'` 验证，包括真实子进程文件大小限制导致的中途写失败；测试不修改正式数据。
