## 为什么上次仍有大量 0

上次规则要求旧段与上游覆盖区间的国家名完全一致且代码唯一。wlzn 对多数国外国家采用英文名称，旧维护数据使用中文；两份库的部分区间归属也存在不同，因此即使“日本”明确对应 JP，原规则也会因字符串或区间不匹配而保留 0。

现在按保留的国家名称查表：中文标准名称使用 Unicode CLDR release-48，旧别名采用显式列表，国家名去除两端空白，且只修正已核对的国家误填，不做模糊匹配。别名包括印尼→ID、孟加拉→BD、波黑→BA、刚果金→CD 等。映射与出处在 `scripts/data/国家名称代码映射.json`，许可证保留于 `scripts/data/UNICODE-LICENSE.txt`。

参考来源：[Unicode CLDR 中文名称固定版本](https://github.com/unicode-org/cldr/blob/release-48/common/main/zh.xml)、[ISO 3166 国家代码说明](https://www.iso.org/iso-3166-country-codes.html)。正式名称代码覆盖 249 个国家地区，科索沃 XK 是另行按 wlzn 数据约定采用的特殊代码，并非正式 ISO 分配代码。

## 与 wlzn 的比较

固定比较 `f8b0792:data/ipv4_source.txt` 和同提交 IPv6 文本：

- wlzn 直接在数据末列保存代码，没有单独配置；IPv4 只有 14 段 Reserved 使用 0，IPv6 有 16 段。
- wlzn IPv4 科索沃 38 段使用 XK，IPv6 46 段使用 XK；本分支对自己的 46 段科索沃记录统一使用 XK。
- wlzn 未使用 AC、EU、AP、AN。Saint Martin 使用 MF，Sint Maarten 使用 SX；旧标签“圣马丁”未注明具体一侧，不能仅凭中文泛称断定。
- 旧“欧洲”的地址在上游有 US、FR、DE 等不同代码，少数单个旧区间甚至覆盖多个上游国家；旧科索沃部分地址在上游也已变为其他国家。直接按地址抄代码会与自有国家字段冲突，本轮不改变你的国家信息或拆分原区间。
- 旧“阿森松岛”对应区间在上游使用 CY，旧“安的列斯”对应区间在上游分别为 CO、AR；不能把这类代码当作旧国家名称的正确代码。

## 可重复验证

```bash
python3 scripts/补齐IPv4国家代码.py data/ipv4_source.txt /tmp/ipv4-country-codes.txt
python3 scripts/验证IPv4迁移.py
python3 -m unittest discover -s scripts -p 'test_*.py'
mvn -o -f binding/java/pom.xml test
```

国家代码补齐脚本只写独立输出，处理前校验七列及 IPv4 连续覆盖；回归校验同时检查旧原件哈希、区间、省、市、ISP 逐行不变，国家仅应用已确认修正规则、末列与映射表一致、文本与 xdb 在全部 IPv4 地址空间映射一致。初次迁移脚本也已采用名称优先规则，未知名称仍保留原有严格区间匹配兜底。

未提交或推送。本轮没有修改 Java 代码；原有维护工具已支持末列国家代码。
