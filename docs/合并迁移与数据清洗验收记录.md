## 清洗规则与结果

旧格式：`起始IP|结束IP|国家|code|省|市|ISP`。

新格式：`起始IP|结束IP|国家|省|市|ISP|国家代码`。

旧 code 经全量检查均为 0，不具有实际国家标识信息。经用户确认，以 wlzn 原始 IPv4 区间为参考：仅当旧段覆盖的全部上游子段国家名称一致、代码非空非 0 且唯一时补码，否则为 0。实际结果为 **67653 段补齐国家代码，652248 段保留 0，总计 719901 段**。

没有替换自维护国家、省、市、ISP，没有合入上游 IPv4 地域变更，没有擅自统一简称或保留地址标签。新版原生五字段返回值与旧版字段顺序不同，下游不能继续沿用旧字段下标。

全部 IPv4 文本区间从 0.0.0.0 连续覆盖至 255.255.255.255，无断档、重叠、倒置或非法地址。旧文本与旧 xdb、新文本与新版 xdb 分别按所有索引区间交集核对，完整空间映射差异均为 0。新版文本逐行核对，区间与原有四项归属信息全部保留。新版 xdb 可因索引拆分、时间戳及国家代码变化而与旧库大小、哈希不同。

## 自有代码适配

自有 merge 包及采集器、资源保留。POM 保留 fastjson2 与 nacos.common 依赖，Java 8 配置及新版 MakerApp 打包入口。shade 排除依赖中因重新打包而失效的 SF/RSA/DSA 签名元数据，实际 jar 启动及清理工具执行通过。

- `RegionItem` 改为读取新版七列顺序，code 属性当前表示末列国家代码。
- `MergeRegionItem` 同时接受历史七列与当前采集器八列 CSV；补丁继续只更改国家、省、市，保留源段 ISP。
- `MergeTest` 支持原有两参数覆盖行为，增加第三参数输出到独立文件。按 /24 与每个源段交集拆分，前后区间归属不变；国家变化时将过期国家代码清为 0。只合并相邻且全部地域字段与代码一致的段。校验全部完成后经同目录临时文件替换输出。
- `ReplaceTest` 去除硬编码 Windows 路径，以输入和独立输出路径运行；仅清理新版省、市列末尾“省”“市”，不修改国家、ISP、代码。拒绝覆盖原件。
- `IpConveter` 增加 IPv4 四段、数值范围校验，防止非法地址进入区间算法。

新增实现使用 JDK 文件及原子移动 API。已检索公共工具；通用流拷贝不提供本流程所需的区间协议校验、字段语义及同目录原子替换，因此未重复封装公共流工具。

采集工具仍有外部请求和资源覆盖行为，本轮未实际调用供应方接口。补丁处理仍按每个补丁遍历源段，未将原有批处理复杂度视为已优化或完成性能验收。

## 使用方法

在仓库根目录执行。维护命令先输出候选文件，人工核对后再决定替换文本；生成库也先输出候选。

```bash
# 省市名称清理（可选；迁移本身没有改变已有省市名称）
java -cp maker/java/target/ip2region-maker-3.1.0.jar org.lionsoul.ip2region.merge.ReplaceTest data/ipv4_source.txt /tmp/ipv4-cleaned.txt --source-format=latest

# 应用采集补丁（补丁文件替换成实际文件）
java -cp maker/java/target/ip2region-maker-3.1.0.jar org.lionsoul.ip2region.merge.MergeTest data/ipv4_source.txt /tmp/merget.txt /tmp/ipv4-merged.txt --source-format=latest

# 新版 IPv4 制库
java -jar maker/java/target/ip2region-maker-3.1.0.jar --src=data/ipv4_source.txt --dst=/tmp/ip2region_v4.candidate.xdb --version=ipv4

# 冻结迁移结果全量校验（后续日常数据更新后应建立新基线）
python3 scripts/验证IPv4迁移.py
python3 -m unittest discover -s scripts -p 'test_*.py'
```

初次迁移复现工具为 `scripts/迁移IPv4数据.py`，依次接收旧文本、wlzn 原始 IPv4 参考文本、独立输出。不要将当前已迁移的 `ipv4_source.txt` 当作原始上游参考。原始参考可从固定提交 `f8b0792:data/ipv4_source.txt` 提取，避免今后 wlzn 分支移动改变补码结果。
